# Materials Testing & Characterization Virtual Lab

**Version 2.1** · Developed by Dr. Vignesh Nayak Ullal, Department of Mechanical Engineering, Mangalore Institute of Technology & Engineering (MITE), Moodbidri · [CC BY-NC-SA 4.0](LICENSE.md)

Live site: <https://nayakvignesh113-bot.github.io/Materials-Testing/>

A static, dependency-free virtual laboratory with 22 experiments. Each experiment runs through eight stages:

**Pre-test → Theory → Operate → Experiment → Validation → Numericals → Post-test → Report**

Every run is generated by a physics-based model with handbook material data plus instrument resolution and specimen scatter, so each student gets their own numbers.

## What is new in version 2.1

- MITE logo in the site header, on every lab report and on certificates.
- Each *Submit to faculty* saves the full report to the faculty's Google Drive; the Faculty page (`#faculty`) has a **Submissions & reports** tab to download one report or a whole class in one file, and to **issue certificates** without a request.
- Certificates can be downloaded from their verification link; faculty can copy that link for a student.
- The feedback form asks for the class code (feedback without it was being filed under *Rejected*).
- **Update `Code.gs` in your Apps Script and deploy a new version** (see `apps-script/SUBMISSIONS_SETUP.md`).

## What is new in version 2.0

- **Narrated explainer** on every Theory tab: an animated, voiced walk-through of the apparatus and test (2–3 scenes) with concept checks; a wrong answer replays the scene. Results go into the report.
- **Listen** button that reads the theory aloud paragraph by paragraph, with highlighting and speed control.
- **Safety briefing** (hazards, PPE, safe practice, emergency) that must be acknowledged before the machine unlocks; the time is recorded in the report.
- **Do-it-yourself set-up**: students choose the set-up actions (measure, mark, grip, attach extensometer, zero…) in the right order. An out-of-order action trips an **interlock alarm** that explains why. A *Watch demo* mode plays the sequence instead. The mode and alarm count are recorded.
- **Tools and consumables** table and a **simulator status** panel (Validated / Partly validated / Teaching model, with sources) on every Theory tab.
- **Numericals** stage: 3 randomised problem types per experiment (66 in all), answers within ±2 %, graded hints and worked solutions.
- **Report**: watermarked with the Report ID and student name, new *Laboratory record* section (safety, set-up, explainer, numericals, validation, feedback), extended assessment summary.
- **Feedback form** that must be completed before printing, downloading or submitting.
- **Submit to faculty**: sends the report summary to the faculty's Google Sheet (see `apps-script/SUBMISSIONS_SETUP.md`), protected by a class code.
- **Certificate of completion** per experiment: once the student has passed the post-test (60 % by default), checked results, given feedback and submitted the report, they request a certificate; the faculty approves it in the Google Sheet or on the `#faculty` page; the student then downloads it as PDF or PNG. Each certificate has an ID and a public check at `#verify-<ID>`.
- **About & validation**, **Compare materials**, side navigation rail, citation and licence.

## Hosting on GitHub Pages

Upload these to the repository root, keeping the folders:

| Item | Needed on the site? |
|---|---|
| `index.html` | Yes: the whole lab in one file |
| `config.js` | Yes: the submission URL (empty = submission off) |
| `audio/` | Yes, for narration (about 15 MB). Without it the explainer runs with captions only |
| `apps-script/` | No: the Google Sheet receiver and set-up guide for faculty |
| `assets/`, `dev.html`, `tools/` | No: source files for editing and testing |
| `README.md`, `LICENSE.md`, `CITATION.cff` | Recommended |

Then **Settings → Pages → Deploy from a branch → main / (root)**. Each experiment has its own link, e.g. `…/#tensile`, `…/#jominy-s-operate`; also `…/#about` and `…/#compare`.

## Report submission to a Google Sheet

Follow `apps-script/SUBMISSIONS_SETUP.md` (about 10 minutes). Paste the web-app URL into `config.js`. Use a separate sheet from the NTM lab, because the columns differ.

## Editing

1. Edit files under `assets/` (open `dev.html` through a local web server to see changes, e.g. `python3 -m http.server`).
2. Run `node tools/test.js` (must end with `fails: 0`).
3. Run `node tools/build.js` to rebuild `index.html`, and upload it.

If you change explainer lines (`expl.js`) or theory paragraphs, regenerate the affected audio: delete those MP3s and run `node tools/narration/extract.js` then `python3 tools/narration/generate.py audio` (see `tools/narration/README.md`). Theory audio is matched to paragraphs by position.

## Adding or editing an experiment

Each file calls `LAB.register({...})` with:

- `id, no, cat, title, std, short, aim, objectives, apparatus`
- `params` — operator settings (`select`, `num` or `range`)
- `simulate(p, rng)` — returns `{ plot, plots, readout(f), specimen, obs, truth, dur }`
- `svg(p)` and `anim(svg, f, sim)` — apparatus drawing and animation; optional `liveView`, `afterRun`, `expExtra`, `reportFigs`
- `calcs(sim, p)` — results the student must enter, with `truth` and tolerance (`tol` relative or `abs`)
- `reference(sim)`, `sample(sim)`, `uncert(sim)`, `conclude(sim)` — validation table, worked calculation, uncertainty rows, draft conclusion
- `theory, summary, formulas, procedure, opSteps, precautions, applications, errors, discussion, refs`
- `pre`, `post` — five multiple-choice questions each `{ q, o:[…], a, why }`
- Set-up steps: add `{ op, title, note, d, draw(layer, u, ctx) }` entries under the experiment id in `assets/js/setup.js`. They play before the test (students can skip them or switch them off).
- Nomenclature: add `[symbol, meaning, unit]` rows under the experiment id in `assets/js/nomenclature.js` (or a `nomenclature` array in the definition). It appears in the Theory stage and the report.

- Explainer: add `scenes` under the id in `assets/js/expl.js`; numericals: three generators under the id in `assets/js/numericals.js`; safety and tools: `assets/js/safety.js`; validation status: `VALID` in `assets/js/site.js`.

Run `node tools/test.js` after editing to check every parameter combination.
